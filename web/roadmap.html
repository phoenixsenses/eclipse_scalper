Roadmap

Twelve phases,
in order

The order is not a preference. The registry and the bus come before any agent moves onto them, and Security lands before Eclipse starts consuming the outside world.

What is public here
What each phase has to deliver and what state it is in. There are no dates on this page and there will not be. A phase is called closed only after an independent review says so, and that word describes the code, never a market result.

01 How a phase closes

Nobody approves their own work.

Each phase runs the same five steps, and the steps are never merged. The value of a review is its independence: if one actor writes an artifact and blesses it in the same pass, the blessing carries no information. So a review reads and reports; it changes nothing. Corrections are a separate step, and they are re-reviewed.

Time pressure is not a reason to compress this. A phase that skips a step is not a faster phase, it is an unreviewed one.

The gate, in five steps
01Implement
02Review
03Correct
04Re-review
05Accept

Steps 02 and 04 are read-only and are not run by whoever wrote the code.

Review scope
read-only; edits nothing
Failing test
a defect in the code until argued otherwise
Claims
checked against the artifact, not the intent
Between steps
a human decides whether to proceed

02 Where the work stands

Two phases closed, one in progress, nine untouched.

Each row carries an implementation state, not a health state. Nothing in Eclipse is running: Accepted means the code exists and an independent review passed it, Building means it exists and is under construction, Design means it is specified and unbuilt, Planned means neither.

Phase 01 Master Center foundation The registry, the policy layer and the decision journal that every other phase reports into. Accepted
Phase 02 Event bus & agent registry One bus, one schema, one way to declare what an agent may publish and read. Its rules are executable, not documentary. Accepted
Phase 03 The scalper becomes the Alpha Agent The existing research engine stops being the product and becomes one agent beneath the Master Center. It publishes candidates; it never publishes outcomes. Building
Phase 04 Security Guardian Identity, scope and denial for every agent, before Eclipse starts consuming anything from outside itself. Planned
Phase 05 Global Market Intelligence Context as a first-class input: macro, cross-market and news state, published as events rather than read ad hoc. Planned
Phase 06 Continuous research engine Research as a service on the bus — datasets, arms and refutations produced on a schedule instead of by hand. Planned
Phase 07 Risk Governor The only agent that may authorise a candidate, and the only one that may refuse one. Nothing reaches execution around it. Planned
Phase 08 Execution Gateway The single place that can talk to a venue, holding the only credentials that exist and acting only on an authorisation. Planned
Phase 09 Organization-wide PR Guardian Every change to every repository reviewed by the same standard the research is held to. Planned
Phase 10 Observability Traces, metrics and logs on one schema, so a stale process shows as stale rather than as healthy. Planned
Phase 11 Dynamic agent spawning Agents registered on demand for a question, with the same contract and the same permissions as a permanent one. Planned
Phase 12 Cross-market intelligence More than one venue and more than one asset class under the same registry, bus and risk authority. Planned

03 What closed phases 01 and 02

A rule that a caller can walk around is documentation.

The foundation was accepted only on the second attempt, and the finding that failed the first one is the reason the phase is worth anything: several of its rules were enforced at a convenience layer, so any caller who built the underlying object directly bypassed them. The rules were stated in the README as executable. For three of them that was not true.

No amount of self-review had surfaced it. Enforcement moved down to the layer that cannot be bypassed, the rules became tests, and the set is now frozen — changing one re-opens the gate and requires a fresh independent pass.

What the foundation guarantees
Registration
an agent declares what it publishes and reads
Declaration
is not a grant; both are reported separately
Schema
additive only; a rename is a major version
Unknown subject
refused, not routed
Failure mode
closed — an unproven path does not open

Accepted = implemented and independently reviewed. It says nothing about any market.

04 Phase 03, in progress

Candidates cross the bus. Outcomes never do.

The research engine is being turned into an agent. The hard part is not the wiring, it is the boundary: a sealed arm accumulates its record untouched, so what the Alpha Agent may publish is a candidate — this event, now, under this arm — and never a result, a total or any summary that implies one.

The adapter is written and reviewed; it is deliberately not connected to a live path. Publication is refused unless the thing being published carries the exact shape of the frozen producer that is allowed to make it.

Boundary rules being enforced
Publishable
a candidate at the moment it forms
Never publishable
an outcome, a total, or a comparison
Identity
shape is not provenance; both are checked
Mutation
a matured record is refused, not filtered
Backfill
refused; an old anchor cannot be published late

Not wired to a live path. No order, no venue, no credential is involved.

05 What is deliberately not here

The roadmap has no dates, and the last phases are the least certain.

A phase is listed because the architecture needs it, not because a date exists for it. The further down the list, the more the description is an intention rather than a plan — and the earlier phases are allowed to change what the later ones mean.

Not on this roadmap
Delivery dates

architecture

Eclipse is a set of independent agents that share a bus, a registry and a policy. Nothing in the system talks to anything else by name.

01 Topology

One bus, one registry, many agents.

The Master Center sits above the bus rather than in front of it. It does not relay messages and it is not a bottleneck — it decides who may join, what each participant may say and hear, and it writes down what happened.

Remove any single agent and the rest keep running. That is the test the topology has to pass.

02 The agent contract

Every agent registers the same way.

There is one shape for joining the system, and it is the same whether the agent is permanent or spawned for the next forty minutes. If a field cannot be filled in, the agent does not start.

The registration is the security boundary. Subscriptions that were not declared are not delivered.

03 Event model

Subjects are the API.

Subjects are hierarchical, so a subscriber can take a whole family or one leaf. Schemas live in a shared package and are versioned independently of the agents that use them — a publisher upgrading its schema does not force every subscriber to redeploy.

Streams that matter are persisted, so an agent that was down can catch up rather than silently miss the window.

04 Environments

Six environments, one hard border.

Dev, test and research share a world. Shadow and paper mirror production behaviour without touching money. Production is a separate security domain with its own secrets, its own network and its own approvals.

The border between research and production is the one that is never relaxed for convenience.

05 Repositories

One repository per boundary.

Repositories follow the agent boundaries, so ownership and permissions line up with the architecture instead of cutting across it.

eclipse-shared is the only common dependency: event schemas, the agent protocol, shared models and the SDK. Everything else depends on it and nothing depends on anything else.

06 Development workflow

Branch, push, review, merge.

Nothing reaches a default branch without a pull request, and no pull request merges without PR Guardian and a human. Branch names carry their intent so the changelog can be assembled from history rather than from memory.

07 Principles

Eight rules that do not change.

Everything above is an implementation and can be replaced. These are the constraints that any replacement still has to satisfy.

01 — Agents propose

An agent produces candidates and findings. It does not produce orders.

02 — Research proves

A claim is worth what its out-of-sample evidence is worth, and no more.

03 — Risk authorizes

No position exists without an explicit, recorded authorization.

04 — Execution acts

One component reaches the exchange. One component holds the keys.

05 — Security controls

Deny by default. Every grant is explicit, scoped and logged.

06 — Events communicate

No agent depends on another agent's implementation, address or uptime.

07 — Everything is versioned

Strategies, agents, schemas, datasets and experiments all carry versions.

08 — Everything is auditable

Why a trade happened — or did not — is answerable long after the fact.

Security architecture

Deny
by default

A new agent arrives with no identity, no secrets, no network route and no subjects. Every capability after that is a decision someone made and someone can point to.

01 Onboarding an agent

Security grows with the system, not after it.

Adding an agent is a security event before it is an engineering one. The sequence is fixed and cannot be partially completed: an agent that fails validation does not start in a degraded mode, it does not start.

This is why the security surface does not fall behind. It is not a sweep performed later — it is the only way in.

Identity issued, named, scoped
Permissions explicit grants
Secret policy which secrets, which purpose
Network policy what it may reach
Event access subjects read and written
Logging obligations declared
Validated then, and only then, it runs

02 Ten layers

Each layer assumes the one above it has already failed.

No single control is trusted to hold. The question each layer answers is: if everything outside me is compromised, what can still not happen?

01 Private source control no public repository, no public fork
02 Private network no internal service is internet-reachable
03 Service identity every agent authenticates as itself
04 Least privilege grants are explicit, scoped and revocable
05 Secrets isolation one holder per secret, one purpose
06 Environment separation research cannot reach production
07 Automated PR security secret and dependency scanning before merge
08 Audit logging append-only, covering grants and denials
09 Risk governor authorization sits in the order path
10 Execution isolation keys exist in exactly one component

03 Permission model

Three lists per agent.

04 Secret management

Nothing below ever reaches a repository.

Development reads from a local environment file that is never committed; production reads from a secret manager with per-identity policies and rotation. A committed .env.example documents the shape without carrying a value.

Exchange keys are issued with trading scope only. Withdrawal permission is not enabled on any key Eclipse holds, so the worst case for a compromised gateway is bad trading, not a drained account.

05 The border

Research and execution are different networks.

Research workloads are the most numerous, the most experimental and the most likely to run code that was written quickly. They sit in a network with no route to the exchange endpoints and no read access to the production secret store.

This is not a policy that a developer can forget to follow. There is no route.
